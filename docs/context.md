# 项目上下文

## 项目目的

Trading Codex 是面向单个操作者的个人 A 股决策工作区。它把时点历史数据和
开盘时段快照转换为可审计的交易提案，再将人工录入的成交同步到本地组合镜像。

## 主要工作流

1. 同步并验证历史行情和开盘时段市场数据。
2. 使用防止信息泄漏的 walk-forward 回测研究策略。
3. 生成确定性的基础目标组合，可选地审阅受约束的 AI 分配提案，并执行硬风险控制。
4. 展示包含价格、失效时间、依据和风险标记的可执行信号。
5. 记录实际成交，并比较基础组合、AI 调整组合和实际组合。
6. 使用完全一致的数据、策略、配置和模型版本重放任意决策。

## 目标

- 让每个信号都可重现、可归因。
- 在评估表现前，先建模 A 股交易约束和成本。
- 随市场状态变化，在预先批准的策略之间调整。
- 让 AI 用于研究、审阅和受约束的分配，但不授予其控制风险或成交的权限。
- 提供信息密集、安静克制且适合每日反复使用的决策界面。

## 非目标

- 在产品初期自动连接券商执行交易。
- 亚分钟级交易或高频交易。
- 多用户、商业化或高并发运行。
- 将免费市场数据 endpoint 视为永久稳定的契约。
- 在 AI 生成策略的同一天将其投入使用。

## 架构

系统是一个本地模块化单体，包含两个长期运行的进程：FastAPI API/worker 边界和
React Web 客户端。市场数据使用不可变 raw artifact 和规范化 Parquet 数据集；
DuckDB 仍是计划中的查询层，事务状态计划使用 SQLite。

共享决策管线与具体框架无关：

```text
时点数据 -> 特征 -> 市场状态 -> 策略意图 -> 分配
  -> 可选 AI 提案 -> 确定性风险 -> 执行计划 -> 账本
```

RQAlpha 是已选择的可替换执行回测适配器，与策略代码和主应用运行时隔离。
Qlib 保留给后续因子和机器学习研究使用。

## 长期约束

- 运行目标是 Asia/Shanghai 时区的 ARM64 主机。
- 历史决策和日常决策必须使用同一条领域管线。
- 所需数据过期或不一致时，决策必须 fail closed。
- 成交账本仅允许追加；纠错使用补偿事件。
- 用户录入的成交是实际组合镜像的事实来源。
- 密钥、raw 市场数据和生成的实验 artifact 不得提交。

## 术语

- **基础组合**：仅由确定性策略和风险逻辑驱动的模拟组合。
- **AI 组合**：包含已批准 AI 分配增量的模拟组合。
- **实际组合**：只由人工记录的成交推导出的组合镜像。
- **决策运行**：一个决策检查点全部输入和输出的不可变记录。
- **时点视图**：拒绝返回晚于声明 `as_of` 时间戳之信息的数据接口。
