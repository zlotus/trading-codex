# ADR-0012：限定为低频研究和人工交易记录工作区

- 状态：Accepted
- 日期：2026-08-12
- 取代：无
- 被取代：无

## 背景

仓库已具备历史行情、共享决策管线、回测、风险检查、AI-shadow、append-only 账本和人工成交
录入能力，但“交易决策系统”这一简称容易被理解为自动券商执行或高频量化平台。两者会显著改变
数据时效、执行可靠性、权限、安全、监管和运维边界，也不是本仓库要解决的问题。

实际需求是使用本地可审计数据分析行情，生成、回测和调试包括网格交易在内的低频策略，并记录
人工完成的交易以供对账和复盘。

## 决策

1. Trading Codex 定位为本地单用户的 A 股行情分析与低频策略工作区，覆盖策略生成、回测、调试、
   可审计交易提案、人工交易记录和复盘。
2. 策略和分配逻辑继续独立于回测与实时数据框架；历史和日常决策继续使用同一共享领域管线与
   显式 `as_of` 边界。
3. AI 只能提供研究或受约束的分配提案，不能绕过确定性风险检查，也不能创建可执行成交。
4. 实际组合只由用户人工录入的成交和现金事件推导。自动券商 gateway、自动下单和任何代替用户
   执行交易的路径均为产品范围外，而不是等待实现的延后事项。
5. 高频交易、亚分钟策略和短于 5 分钟的决策/执行周期均为范围外。当前日频 EOD 和精确 09:35
   contract 是用于低频研究与日常决策的边界，不承诺低延迟或高吞吐。

## 理由

将研究、提案与人工执行分开，能保持系统本地、单用户、可重放和可审计，也与 append-only 账本
及三轨归因一致。排除自动券商执行和高频场景后，项目可以优先保证数据时点、策略正确性、成本、
风险、回测证据和交易记录质量，而不引入与目标无关的低延迟和实盘执行复杂度。

## 考虑过的方案

- 把自动券商 gateway 作为后续里程碑：拒绝，因为这会暗示产品最终承担自动执行权限，并持续影响
  当前 API、安全和运维设计。
- 同时支持高频和低频策略：拒绝，因为现有 BaoStock、Parquet、机械盘和一次性调度边界不适合
  低延迟执行，而且高频需求会破坏当前以可审计性和 fail closed 为先的取舍。
- 只保留纯回测工具：拒绝，因为人工交易记录、actual 组合对账和复盘是明确的主要工作流。

## 后果

- 产品文档、UI 和计划必须使用行情分析、低频策略、人工录入与复盘语义，不能暗示自动执行。
- 外部 timer 可以触发数据准备、分析或提案任务，但不能触发券商成交。
- 新策略仍可扩展，但必须适合现有低频决策点、显式数据时点和确定性风险边界；超出范围的执行
  需求应在仓库外另建系统，而不是扩大本应用权限。
